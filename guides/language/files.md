# Files and Modules

Catena 0.1.16 defines how source files relate to modules. With the lexical
layer complete, every `.cat` file now has one deterministic identity.

## File units

A Catena source file carries exactly the `.cat` extension; anything else is
not Catena source (`FIL001`). A file contains at most one module; two or
more module declarations are invalid (`FIL002`). A file with no module
declaration is a valid no-module file — empty, whitespace-only, or
comment-only files are fine, and builds ignore them.

## Names and matching

The module name comes from the declaration, never the filesystem. File-level
module names are ASCII uppercase-initial words (`Parcel`, `MyMod2`), the
same spelling the JSON and kernel frontends already accept; lowercase,
digit-initial, hyphenated, or Unicode names are invalid (`FIL003`).

When a module is declared, the file basename minus `.cat` must equal the
declared name — `Parcel.cat` declares `Parcel`, and anything else is
`FIL004` with both names reported. Matching is byte-exact and case-sensitive
(`parcel.cat` does not match `Parcel`). No-module files match no basename
and are never reported as mismatched.

## Generated markers

A generated file begins with one exact first-line plain comment:

```catena
// catena:generated by my-tool
```

The tool identifier is ASCII letters, digits, underscore, and hyphen. Only
layout whitespace may precede the marker; the same text anywhere else — a
later comment, a `///` documentation comment, a literal — is ordinary
content. A first-line comment that starts the marker text but gets the
grammar wrong (spacing, empty or invalid identifier, trailing words) is
`FIL005`. Markers carry provenance for future build and reproducibility
tooling.

## Diagnostics

| Diagnostic | Meaning |
| --- | --- |
| `FIL001` | the filename does not carry the `.cat` extension |
| `FIL002` | more than one module declaration in one file |
| `FIL003` | a module name is not an ASCII uppercase-initial word |
| `FIL004` | the declared name does not equal the file basename |
| `FIL005` | a first-line generated marker fails the exact grammar |

## Current boundary

`Catena.resolve_file_unit/4` consumes source bytes, a filename, and
parser-supplied module-declaration events; the concrete module-header
syntax remains future declaration-grammar work. The resolver does not
tokenize source, parse declarations, resolve names, or emit interfaces or
BEAM.

The normative contract is the research repository's
[Files and Modules Specification](https://github.com/pcharbon70/catena-research/tree/main/60-specification/files-and-modules).
